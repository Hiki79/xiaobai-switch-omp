# XiaoBaiSwitch 7 号 Logo 近似性初筛

- 检索日期：**2026-08-15**
- 候选对象：新版九宫格 **7 号**
- 候选特征：深灰/黑色圆盘；中央白色圆脸；两枚深色点眼；从中央向左分叉出两条细白线，并以空心圆节点结束；整体为柔和、极简风格。
- 预期使用：桌面软件/开发工具，核心用途为在站点、AI 模型与 Claude Code/Codex 配置之间进行切换。

> 本文是设计阶段的公开资料初筛，不是商标法律意见，也不证明某一标志可注册或一定不侵权。判断“来源混淆”通常还要结合具体国家/地区、在先权利、商品与服务、实际使用方式、知名度等因素。

## 结论摘要

在本轮检查的官方品牌资产中，**没有发现与 7 号完全相同的 Logo**。不过，7 号同时采用了三个在开发工具领域较常见的视觉元素：

1. 圆形深色载体；
2. 中央双眼白色角色；
3. 分叉线与圆形端点。

单独看，这些大多是通用视觉语言；组合后最值得注意的是 **GitKraken**。其当前官方图标同样以圆形围合、中间双眼角色及外伸线条/触手为主，而且产品同属开发者工具。在 16–32 px 的应用图标尺寸下，两者可能产生“同一视觉家族”的第一印象。因此，7 号按当前构图的**设计撞款风险评为中等**，但尚未发现足以支持“复制”或“必然混淆”的材料。

建议保留 7 号的“小白 + 分流”概念，但在正式替换前至少做一次轻量差异化：把中央脸的轮廓设计成 XiaoBaiSwitch 独有的不对称形状，并让左侧分叉明显成为两条“切换轨道”，避免像触手或围绕角色的肢体。仅改颜色不足以解决结构近似。

### “通用符号”与“可能造成来源混淆”的分界

| 元素 | 初筛判断 |
| --- | --- |
| 分叉线、圆节点 | 在版本控制、网络拓扑、工作流、AI 编排中广泛使用，本身更像功能隐喻。只有当节点数量、角度、路径和载体都接近某一具体品牌时，风险才明显上升。 |
| 两枚点眼的极简白脸 | 单独看非常常见；放进圆形开发工具图标并配合外伸线条后，会更靠近 GitKraken/章鱼类吉祥物的视觉家族。 |
| 黑色或深灰圆盘 | 常见的应用图标载体；公开图像初筛中可见大量“黑圆 + 白色网络/角色”的非同源图形，因此它本身不能作为近似结论。Rebel.com 当前官方主标志也并非这一构图。商标检索通常不能只依赖颜色差异。 |
| “深色圆盘 + 双眼白脸 + 左侧分叉空心节点”的整体组合 | 比单个元素更有辨识度。当前最大的薄弱点不是 Git/n8n 的通用节点，而是中央双眼角色在圆形围合中与 GitKraken 的小尺寸轮廓接近。 |

## 官方商标数据库核对

本轮可确认各入口、检索能力和限制，但**没有生成可主张“零近似注册”的正式结果集**。最终独立 SVG/PNG 已在设计落地阶段生成，但本轮没有把文件提交到交互式官方数据库；同时 WIPO 明确禁止自动查询和抓取。以下记录如实区分了“已核对功能”与“未实际提交图像”。

### 1. WIPO Global Brand Database

- **已核对**：入口可访问；可按文字、持有人、商品/服务、图像相似度等组合检索。图像检索接受 JPG、PNG、WebP，并可选择图像策略和裁切关注区域。WIPO 也提供 Vienna Classification Assistant 辅助给图形元素分类。
- **本轮未提交图像**：最终独立图档已生成，但未上传到交互式数据库；且 WIPO 条款禁止自动查询、抓取和批量下载，所以没有用脚本模拟上传或制造结果。
- **建议的人工检索方法**：使用 `assets/brand/app-icon-1024.png`；分别以完整图标、中央“小白”、左侧分叉三个裁切区域检索；限制 Nice 9（可下载软件）与 42（软件/SaaS/技术服务），并分别查看中国、美国、欧盟及 WIPO/Madrid 来源的在先标志。
- **限制**：WIPO 依赖各知识产权局提供数据，国家集合更新可能延迟；其覆盖并非所有国家/地区的实时完整注册；WIPO 明确说明搜索结果不构成对混淆可能性的法律意见，并建议同时查目标国家/地区的官方数据库。

来源（均检索于 2026-08-15）：[Global Brand Database 官方介绍](https://www.wipo.int/en/web/global-brand-database)、[官方 FAQ（含图像检索、覆盖和更新限制）](https://www.wipo.int/en/web/global-brand-database/faqs_branddb)、[官方使用条款](https://www.wipo.int/en/web/global-brand-database/terms_and_conditions)、[Vienna Classification Assistant 官方说明](https://www.wipo.int/en/web/global-brand-database/w/news/2020/news_0006)。

### 2. USPTO Trademark Search

- **已核对**：USPTO 当前系统**不支持反向图片搜索**。图形标志必须先拆解显著元素，再用六位 Design Search Code 或图形文字描述检索。
- **可采用的起始代码**：`26.01.21`（实心/部分实心圆）、`26.01.12`（带线条的圆）、`26.01.02`（单线圆）可作为圆盘、内部线路与空心端点的初步候选；它们不是 USPTO 对本标志的正式编码结论。应分别检索后再组合，并限制 live 记录及 International Class 009/042。
- **本轮未形成可用结果集**：这些几何代码覆盖面很宽；没有反向图片匹配，也没有经过 USPTO 编码的候选图档。仅凭宽泛代码得到的大量结果不能可靠说明“有冲突”或“无冲突”，因此不在本文伪造数量或零结果。
- **限制**：USPTO 联邦库只覆盖美国联邦申请/注册。USPTO 官方建议完整清查还要包含州商标、互联网与普通法使用；相似性也不仅看图形，还看商品/服务是否相关和整体商业印象。

来源（均检索于 2026-08-15）：[USPTO Design Search Codes 官方说明](https://www.uspto.gov/trademarks/search/design-search-codes)、[USPTO 联邦商标检索策略](https://www.uspto.gov/trademarks/search/federal-trademark-searching)、[USPTO Trademark Search 帮助](https://tmsearch.uspto.gov/?page=help)、[USPTO 完整清查说明](https://www.uspto.gov/trademarks/search/comprehensive-clearance-search-similar-trademarks)、[USPTO 混淆可能性说明](https://www.uspto.gov/trademarks/search/likelihood-confusion)。

### 3. EUIPO / TMview

- **已核对**：TMview 当前提供“Search by image”，接受 JPG、PNG、GIF、TIFF，可裁切关注区域，并能按地区、知识产权局、Nice 类别等过滤；其图像库包含 EUIPO、欧盟各局及多国合作局的数据。
- **本轮未提交图像**：最终独立图档已生成，但未上传到交互式数据库，因此只核对入口和方法，没有生成 TMview 相似图列表。
- **建议的人工检索方法**：与 WIPO 一样分别上传完整图标和三个局部裁切；先检索欧盟、美国、中国、WIPO 来源，再限制 Nice 9/42；逐条打开命中记录并回到来源局官方登记簿核验状态、权利人、图样和商品/服务。
- **限制**：TMview 页面明确说明该工具不是官方登记簿，数据本身不产生法律效力。帮助文档还说明，某些参与局不提供特定字段时，相应筛选条件可能不会应用到该局结果。EUIPO 也提醒，相似性报告或无搜索结果都不是穷尽性保证。

来源（均检索于 2026-08-15）：[TMview 官方检索入口](https://www.tmdn.org/tmview/get-detail?lang=en)、[TMview 官方帮助（图像检索与字段限制）](https://www.tmdn.org/static/tmdsview/tmview/helpFiles/en/help.html)、[EUIPO 商标可用性说明](https://www.euipo.europa.eu/en/trade-marks/before-applying/availability)、[EUIPO Vienna Classification FAQ](https://www.euipo.europa.eu/en/help-centre/searches/faq-vienna-classification)。

## 建议的定稿动作

1. **保留概念，修改主轮廓**：中央“小白”不要做成对称的水滴/章鱼头；可改为带一个轻微缺口或偏心圆角的白色“豆形脸”，让剪影在无颜色时也独有。
2. **强化“切换轨道”而不是“触手”**：两条左分支保持严格的轨道几何和独立空心端点，不要沿圆周回卷，也不要增加对称触手。
3. **不要只靠换色规避**：柔和深灰、米白和低饱和蓝可以建立品牌气质，但正式清查会关注黑白轮廓与整体印象。
4. **做小尺寸对照**：以 16、24、32、64 px 并排比较最终稿与 GitKraken、n8n、Git 官方图标；如果遮住文字后仍容易误认，应继续调整脸形或外围载体。
5. **拿最终独立文件重跑官方检索**：完成 SVG 后，再人工上传 WIPO 和 TMview；在 USPTO 用 Design Search Code + Nice 9/42 检索。若计划商用发行或申请商标，再让目标市场的商标专业人士核验完整结果。

## 本轮边界

- 检查范围是公开可访问的官方品牌资产、官方产品页面和官方商标检索说明，不是全球所有在用 Logo 的穷尽搜索。
- 没有使用第三方 Logo 下载站作为结论依据；图像搜索中的第三方结果只用于发现候选，最终判断均回到品牌方官方页面或官方仓库。
- 没有核查未注册但可能享有普通法、著作权或不正当竞争保护的所有图形，也没有核验每个国家/地区的完整权利链。
- “未发现完全相同标志”只适用于本文列出的本轮检查，不等于法律上的可注册或无冲突结论。
